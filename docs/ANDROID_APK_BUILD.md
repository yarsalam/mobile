# ساخت و انتشار APK آزمایشی اندروید

## کاهش حجم دانلود

خروجی مستقیم برای گوشی‌های ARM به دو APK مجزا تقسیم شده است؛ به‌جای یک APK بزرگ که کتابخانه‌های native چهار معماری را هم‌زمان حمل می‌کرد:
- `yarsalam-arm64-v8a.apk`: انتخاب پیش‌فرض برای بیشتر گوشی‌های اندرویدی جدید.
- `yarsalam-armeabi-v7a.apk`: جایگزین برای گوشی‌های قدیمی‌تر ۳۲ بیتی.

اندازهٔ نهایی هر فایل باید از گزارش همان اجرای GitHub Actions بررسی شود؛ کاهش دقیق تا زمان build جدید قابل تضمین نیست. فایل‌های split برای شبیه‌سازهای x86 ساخته نمی‌شوند.

## ساخت و انتشار عمومی

1. workflow در `.github/workflows/android-apk.yml`، lint و Jest را اجرا می‌کند، سپس دو APK مستقل می‌سازد.
2. خروجی‌های موقت در Artifact با نگهداری ۱۴روزه قرار می‌گیرند؛ این لینک‌ها ممکن است به ورود GitHub نیاز داشته باشند.
3. برای انتشار عمومی، ورودی `release_tag` باید یکتا باشد. پیش‌فرض فعلی `test-v0.1.2` است، چون `test-v0.1.1` قبلاً منتشر شده.
4. پس از انتشار، لینک مستقیم هر APK برای کاربران قابل استفاده است؛ برای بیشتر گوشی‌ها لینک arm64 را بفرست.

## وضعیت امضا و محدودیت‌ها

- این نسخه‌های آزمایشی با debug keystore امضا می‌شوند و نسخهٔ نهایی Production نیستند.
- برای انتشار رسمی، keystore اختصاصی و امن لازم است؛ کلید و رمز آن نباید وارد مخزن شوند.
- آدرس API در زمان build تعیین می‌شود و باید DNS، TLS و خود endpointها پیش از توزیع وسیع تأیید شوند.
- برای APK قابل دانلود، از IP خصوصی شبکهٔ توسعه (مانند `192.168.x.x`) استفاده نکن؛ این آدرس‌ها از گوشی کاربران خارج از همان شبکه قابل دسترسی نیستند. workflow چنین IPهایی را رد می‌کند.
