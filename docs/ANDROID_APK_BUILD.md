# ساخت و انتشار APK آزمایشی اندروید

## وضعیت

مخزن از React Native استفاده می‌کند. Workflow موجود در `.github/workflows/android-apk.yml` پس از ادغام در `main` امکان lint، اجرای Jest و ساخت APK آزمایشی را فراهم می‌کند. بیلد در GitHub-hosted runner انجام می‌شود؛ منابع محدود VPS برای ساخت APK مصرف نمی‌شوند.

## ساخت APK از GitHub

1. ابتدا PR مربوط به تطبیق قراردادهای API موبایل را بررسی و ادغام کنید.
2. به تب **Actions** مخزن `yarsalam/mobile` بروید و workflow **Android test APK** را انتخاب کنید.
3. **Run workflow** را بزنید و شاخه‌ای را انتخاب کنید که `src/config/api.ts` را دارد، فعلاً `fix/mobile-api-auth-contracts`.
4. آدرس API را `https://api.yarsalam.top` بگذارید. تا زمان آماده شدن DNS، TLS و بک‌اند، APK ساخته‌شده ممکن است به API متصل نشود.
5. برای ساخت فقط artifact، فیلد `release_tag` را خالی بگذارید. از خروجی اجرای workflow، artifact با نام `yarsalam-test-apk` را دانلود کنید. این artifact موقت است و به ورود به GitHub نیاز دارد.
6. اگر یک لینک عمومی دانلود می‌خواهید، در اجرای دستی `release_tag` یکتا مانند `test-v0.1.0` وارد کنید. در صورت موفقیت build، یک GitHub prerelease عمومی همراه APK و فایل SHA-256 ساخته می‌شود.

## نکات امنیتی و انتشار

- خروجی این workflow با کلید debug اندروید امضا می‌شود؛ فقط برای تست نصب و جریان‌های برنامه است، نه انتشار نهایی.
- برای انتشار production باید کلید امضای اختصاصی و امن تهیه شود. فایل keystore و رمزهایش نباید در مخزن قرار گیرند؛ تنظیم signing باید بعداً با GitHub Actions secrets یا محیط امن محلی انجام شود.
- آدرس API در باینری قرار می‌گیرد و محرمانه نیست؛ هیچ توکن یا کلید سمت سرور نباید در اپ موبایل قرار بگیرد.
- APK تا وقتی سرور، DNS، HTTPS و endpointهای موردنیاز آماده نشده‌اند، صرفاً برای تست نصب و UI مناسب است.
- Workflow ابتدا lint و Jest را اجرا می‌کند؛ اگر این بررسی‌ها شکست بخورند، APK منتشر نمی‌شود.
- لینک artifact موقت و محدود به کاربران دارای دسترسی مخزن است؛ GitHub Release در مخزن عمومی لینک عمومی ارائه می‌کند.
